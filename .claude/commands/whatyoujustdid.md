Review the most recent changes made in this session and explain them clearly to the user.

The goal is to help a user who has been letting Claude Code implement features for a while and now wants to catch up on what was done.

Structure the explanation as follows:

1. High-Level Summary

In 2–4 sentences, explain what was implemented and the overall objective of the changes.

2. Files Changed

List the important files that were modified and briefly describe the purpose of each change.

3. What Was Implemented

Explain the implementation in logical steps.

For each significant change:

* explain what was added, modified, or removed
* explain why the change was necessary
* explain how it fits into the overall architecture

Focus on concepts rather than line-by-line code.

4. Important Design Decisions

Highlight any noteworthy engineering decisions, including:

* tradeoffs considered
* patterns used
* architectural choices
* libraries or technologies introduced
* assumptions made

5. Things the User Should Understand

Identify the key concepts behind the implementation so the user learns from the changes instead of simply accepting them.

If helpful, briefly explain unfamiliar technologies or terminology.

6. Suggested Next Steps

Explain what logically comes next and what remains to be implemented.

Guidelines

* Prioritize understanding over completeness.
* Explain the reasoning behind the implementation, not just what changed.
* Use simple language while preserving technical accuracy.
* Use analogies where they genuinely improve understanding.
* Avoid overwhelming the user with low-level implementation details unless they are essential.
* If there were no meaningful changes in the current session, clearly state that and explain why.
