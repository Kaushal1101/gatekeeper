Review the changes made during the current session and identify all project documentation that should be updated.

The goal is to keep documentation synchronized with implementation so it remains an accurate representation of the project.

Documentation to Update

Update any documentation that describes the current state of the project, including but not limited to:

* Architecture documentation
* Design documents
* Agent skill cards
* Technical documentation
* Implementation notes
* API documentation
* README (if affected)
* Configuration documentation
* Any other project documentation that has become outdated

Project Log

If updating the project log:

* Append a new entry describing the latest work completed.
* Summarize the major implementation changes.
* Record any important engineering decisions or tradeoffs made.
* Record the current Git branch (for example: main, staging, feature/token-bucket, etc.).
* Do not rewrite previous project log entries unless they are factually incorrect.

Guidelines

* Only document changes that have actually been implemented.
* Keep documentation concise, accurate, and technically correct.
* Preserve the existing writing style and formatting of each document.
* Avoid duplicating information across multiple documents when possible.
* If no documentation requires updating, explicitly state that no documentation changes are necessary.
* Do not invent future work or planned features unless the document is specifically intended for future planning.
* Prefer updating existing documentation over creating new files unless a new document is clearly warranted.
